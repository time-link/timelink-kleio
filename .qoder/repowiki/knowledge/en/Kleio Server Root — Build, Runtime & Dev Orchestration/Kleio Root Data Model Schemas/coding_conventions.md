- Every schema entry is a single-element list containing either a bare `{path: <root>}` marker or a `{group: {name, ...}}` block — there are no top-level keys other than these list items.
- Inheritance is expressed declaratively via the `source:` field inside a `group`, never by nesting objects; the inheriting group re-declares its own `arbitrary` slot list.
- Composition of sub-parts is declared with the `part:` list alongside `source:`, allowing a type to both inherit from another group and add named parts.
- Slot names are plain lowercase identifiers (e.g. `atr`, `rel`, `ls`, `referido`, `referida`, `pai`, `mae`, `filho`, `mulher`, `marido`, `pad`, `mad`, `procurador-pad`, `procuradora-mad`, `end`, `local`, `fonte_info`, `cheater`, `agente_financeiro`, `agente_seguros`, `transportador`, `cobrador*`, `recebedor*`, `pagador*`, `tomador*`, `beneficiario*`, `dador*`, `emissor*`, `representante`, `informador`, `defector`, `intermediario`, `fretador`, `receptor`, `destinatario*`, `vendedor`, `comprador`, `fornecedor`, `fiador`, `arrematante`, `quitante`, `quitado`, `abençoador`, `abençoado`, `perdoante-m`, `perdoado`, `vitima-m`, `testador`, `testamentario`, `testamenteiro`, `contraente`, `renunciante`, `procurador`, `escrivao`, `tabeliao`, `juiz`, `autoridade`, `padroeiro`, `apresentado`, `confirmante`, `comerciante`, `proprietario`, `requerente`, `requerido`, `pm`, `ts`, `testo`, `denunciante`, `acusado`, `enfermo`, `remetente`, `endossante`, `endossado`, `debitado`, `recebedor-proc`, `fornecedor`, `fiador`, `arrematante`, `quitante`, `quitado`, `abençoador`, `abençoado`, `perdoante-m`, `perdoado`, `vitima-m`) and are validated solely by membership in the declaring group's `arbitrary` whitelist.
- Portuguese-language variants are created by duplicating the English base (`historical-act` → `pt-acto` → `ato` → `evento`; `object` → `topico`; `abstraction` → `med`/`conf`/`marco`) and swapping only the `name` and any role-slot additions, keeping the same `source:` chain.
- Repeated role patterns are enumerated explicitly rather than templated (e.g. `beneficiario1..6`, `pagador1..5`, `tomador1..5`, `recebedor1..4-proc`, `dador1..4`, `cobrador-representante1..4`, `marido1..3`, `mulher1..3`, `pad1..4`, `mad1..4`, `ppai/pppai/ppppai/mpppai/mppai/pmppai/mmppai/mpai/pmpai/ppmpai/mpmpai/mmpai/pmmpai/mmmpai`), producing large but unambiguous `arbitrary` lists.
