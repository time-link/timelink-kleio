Three cooperating modules form the runtime core:
- `topLevel.pl` (`:-module(topLevel,[...])`) is the single public facade: `clio_init/0`, `stru/1`, `dat/1`, and `readlines/1` orchestrate file I/O, dispatch to lexical/syntactic analysers (`dataSyntax`, `struSyntax`, `lexical`), and accumulate results via `persistence` globals. It imports all other subsystems (`dataCode`, `dataDictionary`, `reports`, `counters`, `logging`, `linkedData`, `yamlSupport`) but exposes only a small stable API.
- `errors.pl` (`:-module(errors,[...])`) centralises error/warning emission through `error_out/1,2` and `warning_out/1,2`, which call `p_error_warn_context/3` to format messages with current source-file, line number, and surrounding lines fetched from `persistence` (`get_value(data_file|stru_file)`, `get_prop(line,...)`). A global `max_errors` cap (default 10) short-circuits further processing via `check_continuation/0`.
- `utilities.pl` (`:-module(utilities,[...])`) provides cross-cutting helpers — list ops (`member_check/2`, `first_n/3`, `l_dif/3`), gensym generators backed by `current_num/2` dynamic facts (both thread-local and shared variants), string/atom case conversion, and an `export/4` query-to-file writer. It re-exports `swiCompatibility` and depends on `persistence` for its gensym counters.

Dependency direction is strictly inward: `topLevel` → `errors` + `utilities`; `errors` → `utilities` + `persistence` + `counters` + `reports`; `utilities` → `persistence`. No module here imports another inside this scope except `topLevel` importing `errors` and `utilities`.
