Three cooperating Prolog modules form a classic lexer → parser → rule engine pipeline:
- `lexical.pl` (module `lexical`) is the tokenizer. It classifies characters via `chartype/2`, exposes dynamic data flags through `data_flag/2` and `set_data_flag/2` (stored in the `data_flags` property bag), and produces tokens with DCG rules `toks/2`, `tok/2`, `num/1`, `names/1`, `dqstring/1`, `tquote/1`. Two entry points `get_tokens(cmd,...)` and `get_tokens(dat,...)` dispatch to mode-specific tokenizers; `process_lexical_props/1` reads the file's `multiple-entry-flag` to remap data flag 8.
- `dataSyntax.pl` (module `dataSyntax`) consumes those tokens line-by-line via `compile_data/1` and the DCG `a_line/2`, `element/1`, `group/1`. It maintains per-file state (`tquoteOn/Off`, `dquoteOn/Off`) using the global value store (`get_value/put_value`) for triple-quote and double-quote spans, and emits calls such as `newGroup/1`, `newElement/1`, `endElement/0`, `newAspect/1`, `storeCore/1` which are accumulated and flushed by `storeEls/1` (from `dataCode`).
- `inference.pl` (module `inference`) declares the public `if/1` operator family (`op(230,fx,if)`, `op(220,xfy,then)`, `op(210,xfy,and/or)`) and contains hundreds of declarative rules of the form `if [sequence(Path), ...] then relation(...).` / `attribute(...).` The predicates `relation/4` and `attribute/3` are not defined here — they are supplied by downstream consumers (e.g. `gactoxml.pl`) that load this module to register auto-relation clauses. A large block of generated rules (prefixed `BEGIN Auto-relation ... v2.1 16-5-2005`) is produced by `make_auto_relation_clauses2` in `gactoxml.pl` and covers ancestor levels up to 4 generations.

Dependency direction is strictly one-way: `dataSyntax` depends on `lexical`; `inference` has no intra-module dependencies and is consumed by higher-level code that interprets its `if/1` clauses.
