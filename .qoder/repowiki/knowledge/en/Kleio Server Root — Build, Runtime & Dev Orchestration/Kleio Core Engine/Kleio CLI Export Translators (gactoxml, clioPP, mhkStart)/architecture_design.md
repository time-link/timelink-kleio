Three cooperating Prolog modules forming the Kleio-to-XML export pipeline:
- `gactoxml.pl` is the main translator implementing the Clio export interface (`db_init/0`, `db_store/0`, `db_close/0`). It dispatches each Kleio group through a `group_export(+GroupType,+ID)` switchboard that matches concrete or derived groups (e.g. `person`, `historical-act`, `authority-register`, `geoentity`) via `group_derived/2` against the gacto2 schema, then emits XML by calling `group_to_xml/3`. It maintains translation state in thread-local flags (`?-thread_local(...)`) and global properties (`set_prop`/`get_prop`) for act/person/autorels context.
- `clioPP.pl` provides `clioPP/2` and `clioPP_close/0`, which walk the current Kleio group tree and emit a copy of the source with explicit `/id=...` attributes on every entity — this is what makes subsequent translations idempotent. `gactoxml` invokes it conditionally when translating `.cli` sources (skipped for `.ids` inputs).
- `mhkStart.pl` is a tiny bootstrap consulted at server startup; it simply consults `swiStart`.

Dependency direction: `gactoxml` → `clioPP` → core engine modules (`externals`, `persistence`, `lexical`, `utilities`, `counters`, `errors`, `inference`, `mappings`, `reports`, `linkedData`, `jsonUtilities`). The module uses SWI-Prolog libraries (`library('sgml')`, `library(http/json)`, `library(filesex)`) for XML/JSON I/O and delegates file rename operations to a shell helper (`shellUtil:shell_to_list`) to work around Windows VirtualBox bugs.
