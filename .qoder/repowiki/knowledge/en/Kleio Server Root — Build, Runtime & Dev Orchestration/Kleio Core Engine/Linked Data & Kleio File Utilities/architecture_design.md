Three independent Prolog modules with no internal cross-imports:
- `kleioFiles.pl` (`kleiofiles`) is the largest utility layer: it resolves Kleio home/conf/source/structure/log directories via a cascade of environment variables (`KLEIO_HOME_DIR`, `KLEIO_SOURCE_DIR`, …) and filesystem heuristics, builds a canonical `kleio_file_set` dict of translation artifacts (`rpt`, `err`, `xml`, `org`, `old`, `ids`, `files.json`), computes their status (`T/E/W/V/D`), and exposes bidirectional `kleio_resolve_source_file/3` / `kleio_resolve_structure_file/3` path mappers used by the rest of the system. It depends on `shellUtil`, `persistence`, `utilities`, `logging`.
- `linkedData.pl` (`linkedData`) stores per-thread link patterns (`xlink_pattern/2`) and data (`xlink_data/2`) in thread-local dynamic tables, parses `@shortName:id` annotations from text via `library(pcre)` regexes, and expands them into URIs using the registered URL pattern with `$1` substitution; it emits warnings through `errors:warning_out/1` when a pattern is missing.
- `apiExports.pl` (`apiExports`) is a thin API shim that delegates export-file retrieval to the `sources` module via `apiCommon`, exposing `exports/5` and `exports_get/3` only.
Dependency direction is one-way: `apiExports` → `apiCommon` → `sources`; `linkedData` → `errors`; `kleioFiles` → `shellUtil`/`persistence`/`utilities`/`logging`. There are no shared predicates between these three files.
