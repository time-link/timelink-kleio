Three sibling entrypoint files form the process-level surface of the application:
- `serverStart.pl` is the CLI orchestrator. It imports `restServer`, `utilities`, `persistence`, and `logging`, then exposes top-level predicates (`run_server`, `run_debug_server`, `run_server_forever`, `debug_server_until_idle`, `run_test_server`, `setup_and_run_server/2`) that configure environment variables (KLEIO_*), set shared properties, and call into `restServer:start_rest_server` / `start_debug_server`. It also contains test harness code using `library(http/http_client)` to drive the running server.
- `restServer.pl` is the actual HTTP service: it declares the module, registers SWI `http_handler`s for `/rest/`, `/json/`, `/forms/upload/`, and the root home page, starts `thread_httpd` with configurable worker threads, token database bootstrapping, CORS, and dispatches requests through `process_rest/1` (REST) and `process_json_rpc/1` (JSON-RPC). Both decoders extract an authorization token via `get_authorization_token/2`, then dynamically invoke handler predicates named by the request method (`Entity(Method,Object,Mode,Id,Params)` or legacy `Method(Mode,Id,Param,Results)`).
- `docServer.pl` is a thin wrapper around `clioStart` that simply calls `doc_server(4040,[])` to serve PlDoc.

Dependency direction is one-way: `serverStart.pl` → `restServer.pl`; `docServer.pl` depends only on `clioStart`. The three files share no mutual imports — they are independent launch scripts loaded by different `swipl -f ...` invocations.
