Three independent leaf modules with no inter-dependencies between them, each exposing a small public predicate set via `:- module/2`:
- `basicio.pl` (`basicio`) wraps SWI-Prolog's `get_code`/`put_code` into tagged `(Code,Type)` char streams using `lexical:chartype/2`, providing `readline2/2`, `getchar2/1`, `putchar2/1`, `get_codes/2`, `get_string/2`; depends on `reports`, `counters`, `utilities`, `lexical`.
- `jsonUtilities.pl` (`jsonUtilities`) bridges Prolog terms to SWI's `library(http/json)`, exporting `dict_json_string/2` (dictionary → JSON string) and the deprecated `prolog_to_json/2` which walks lists/terms into `json_write`-compatible structures; relies only on `library(http/json)`.
- `yamlSupport.pl` (`yamlSupport`) is the YAML schema loader: `stru_yaml/1` and `new_yaml_str/2` drive `library(yaml)`'s `yaml_read/2`, then dispatch each top-level `{Command, Params}` entry through `process_str_command/2` into the existing `struCode:stru*` command pipeline (via `struSyntax:is_kw/2`, `struCode:init_command/1`, `execParam/3`, `close_command/2`). It maintains a file stack (`stru_files_stack`) and read-set (`stru_files_read`) to handle `include` directives and avoid cycles, and normalizes relative paths through `normalize_str_path/2` before resolving with `absolute_file_name/2`. Depends on `persistence`, `kleioFiles`, `reports`, `struCode`, `struSyntax`, `dataSyntax`, `errors`.

Dependency direction is one-way outward: this module is consumed by higher-level translation layers but does not import other shared utilities from this scope.
