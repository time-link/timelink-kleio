The root is a thin orchestration layer around three cooperating children: `core_engine` (SWI-Prolog server), `syntax_definitions` + `root_data_models` (YAML/JSON structure schemas consumed at build time), and `tests_and_fixtures` / `documentation` (consumed by CI/dev). Cross-child wiring happens through Makefile-driven artifacts:
- Version injection: `prepare` reads `kleio.version.number`, `kleio.patch.number`, `kleio.build.number`, `kleio.build.date` and sed-injects `@@VERSION@@`/`@@BUILD@@`/`@@DATE@@` placeholders into `src/sources-structure.yaml` and `src/topLevel.pl`, so the running engine always knows its own version.
- Structure sync: `make yaml-stru-cpy` copies `tests/kleio-home/structures/*.yaml` into `src/stru`, letting the test fixture schema drive the shipped runtime schema.
- Containerization: `Dockerfile` + `docker-compose.yaml` + `.env-sample` package the built image; `make kleio-run-*` sets `KLEIO_HOME_DIR`, `KLEIO_SERVER_PORT`, `KLEIO_EXTERNAL_PORT`, `KLEIO_ADMIN_TOKEN`, `KLEIO_USER` and delegates to `docker compose up -d`, which mounts the host directory as `/kleio-home` so the server persists sources, structures and `.kleio.json` on disk.
- Test bridge: `make test-semantics` and `test-api` invoke scripts under `tests/` against a live container, while `make docs` regenerates the static site from the Postman collection in `api/postman/`.
- Release flow: `build-local` → `tag-multi-stable`/`tag-multi-latest` push multi-arch images to `timelinkserver/kleio-server` and tag git with the patch number; `current-to-stable` snapshots current `src/` into `tests/stable/` so semantic tests compare against the last released baseline.
