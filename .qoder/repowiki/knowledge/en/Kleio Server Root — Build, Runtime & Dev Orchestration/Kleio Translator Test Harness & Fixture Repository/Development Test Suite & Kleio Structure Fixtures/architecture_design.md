Flat collection of ~60 Prolog modules plus a `stru/` fixture directory, all loaded from the same workspace root so tests can `use_module` any other module without an explicit package path.

- Test harness: `tests.pl` is the primary entry point, using SWI's `library(test_wizard)` and `plunit` (`:- begin_tests/1 ... :- end_tests/1`) with `run_tests(Module)` invocations; `test_kleiofiles.pl` is a separate plunit file for the `kleioFiles` module.
- API surface under test: `apiCommon.pl` re-exports `apiSources`, `apiDirectories`, `apiTranslations`, `apiExports`, `apiReports`, `apiGit`, `apiIdentifications`, `apiLog`, `apiStructures`, `apiTokens`; each `api*.pl` implements one REST/JSON-RPC entity (see its header table mapping HTTP method + entity → JSON-RPC function).
- Core Kleio subsystems exercised by tests live alongside the tests as sibling modules: `dataDictionary`, `dataCode`, `dataSyntax`, `lexical`, `inference`, `mappings`, `persistence`, `logging`, `restServer`, `serverStart`, `clioPP`, `gactoxml`, `kleioFiles`, `tokens`, `utilities`, etc. — there is no separate `src/` tree; this directory IS both implementation and test ground.
- Fixture data: `stru/` holds canonical Kleio structure definitions in both legacy `.str`/`.srpt` format and preferred YAML (`elements.yaml`, `groups.yaml`, `sources-structure.yaml`, `pt-sources-structure.yaml`, `system.yaml`, `pt-elements.yaml`, …); `README.md` documents that YAML is preferred and `sources-structure.yaml` is the default entry point.
- Auxiliary dev helpers: `swiCompatibility.pl`, `swiShell.pl`, `swiStart.pl`, `shellUtil.pl`, `threadSupport.pl`, `jsonUtilities.pl`, `yamlSupport.pl`, `gitUtilities.pl`, `verif.pl`, `exputil.pl`, `assertUsage.txt`, `httpd.log`, `qrecord.queries` (auto-generated query log), `xref_kleio.pl`, `kleioExport.xsd`.
