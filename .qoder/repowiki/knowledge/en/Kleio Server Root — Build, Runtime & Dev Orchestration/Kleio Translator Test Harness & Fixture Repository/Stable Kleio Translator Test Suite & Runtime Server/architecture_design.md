The module is a flat collection of SWI-Prolog modules under `tests/stable/` organized around two concerns:

- **Test harness**: `tests.pl` uses `library(test_wizard)` (`begin_tests/end_tests`, `run_tests(Module)`) to assert on core predicates in `utilities`, `swiCompatibility`, and `dataDictionary`. `verif.pl` provides ad-hoc vocabulary collectors for life_story attributes and relation variants. `teste.pl` is a minimal placeholder.
- **Server runtime** (the code being tested): `restServer.pl` boots an SWI HTTP server (`thread_httpd`, `http_dispatch`) exposing both REST and JSON-RPC entry points; it reads configuration from `KLEIO_*` environment variables (`KLEIO_HOME_DIR`, `KLEIO_SOURCE_DIR`, `KLEIO_SERVER_PORT`, etc.) and dispatches calls via `json_exec/4` into per-entity modules re-exported through `apiCommon.pl` (`apiSources`, `apiDirectories`, `apiTranslations`, `apiExports`, `apiReports`, `apiGit`, `apiIdentifications`, `apiTokens`).
- **Translator core** exercised by the tests: `topLevel.pl` exposes `clio_init/0`, `stru/1`, `dat/1`; `dataDictionary.pl` manages groups/elements as dynamic thread-local facts (`clioStru_`, `clioGroup_`, `clioElement_`) with property bags via `persistence`; `lexical.pl`, `struSyntax.pl`, `struCode.pl`, `dataSyntax.pl`, `dataCode.pl` form the lexer/parser/compiler pipeline; `gactoxml.pl` / `kleioFiles.pl` produce XML/Kleio outputs; `mappings.pl`, `linkedData.pl`, `vocabularies.pl`, `inference.pl` add semantic layers.
- **Infrastructure helpers**: `persistence.pl`, `logging.pl`, `errors.pl`, `counters.pl`, `basicio.pl`, `utilities.pl`, `threadSupport.pl`, `tokens.pl`, `kleio_translator.log`, `httpd.log` provide shared state, I/O, logging, token auth, and threading primitives used across all API modules.
- **Startup scripts**: `serverStart.pl`, `clioStart.pl`, `mhkStart.pl`, `dockerStart.pl`, `swiStart.pl` are thin wrappers that set env vars and call `restServer:start_rest_server/0` or `topLevel:clio_init/0`.
- **VS Code integration**: `.vscode/launch.json` configures the Prolog debugger to launch `swipl` with a `start` startup query against the current file.

Dependency direction is one-way: API modules → `restServer` + domain modules → translator core (`topLevel` + syntax/code modules) → infrastructure (`persistence`, `logging`, `utilities`). Tests depend only on the public predicates they exercise.
