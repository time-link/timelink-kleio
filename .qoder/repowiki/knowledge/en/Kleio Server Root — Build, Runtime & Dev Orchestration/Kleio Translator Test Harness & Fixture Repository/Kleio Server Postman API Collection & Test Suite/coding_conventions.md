- Every request sets a unique `id={{request_id}}` query parameter and asserts the echoed `Request-id` response header equals the same value, enabling end-to-end request tracing.
- Authentication is declared at the request level via `auth.type=bearer` with the token read from a Postman variable (e.g. `{{testadmintoken}}`, `{{tester_token}}`, `{{coordinator_token}}`, `{{remotetoken}}`) rather than being hardcoded.
- Assertions are written as inline `pm.test("...", function(){ ... })` blocks inside each request's `event[listen='test']` script, using `pm.response.to.have.status(...)`, `pm.expect(...).to.include(...)`, and header checks instead of external test harnesses.
- Stateful values produced by one request (tokens, random file paths, directory names) are propagated to later requests by calling `pm.environment.set(key, value)` in the preceding request's test script and consumed via `{{key}}` interpolation.
- The test suite follows a fixed lifecycle: invalidate existing users → generate scoped tokens → erase and re-seed `sources/{{test_sources}}` from `sources/{{reference_sources}}` → run feature tests → leave derived variables (`source_1..5`, `dir_1..4`, `deleted_file`) for downstream assertions.
