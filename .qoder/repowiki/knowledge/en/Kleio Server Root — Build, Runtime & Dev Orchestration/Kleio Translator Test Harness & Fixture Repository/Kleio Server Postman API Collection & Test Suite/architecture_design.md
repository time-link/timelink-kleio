Two complementary Postman v2.1 collections live side-by-side: `api.json` (named 'kleio-server') is a browsable API reference covering both the `/json/` JSON-RPC-V2 endpoint and the `/rest/*` REST endpoints across folders like `tokens`, `sources`, `structures`, `translations`, `files`, `kleioset`, `exports`, and `reports`; `tests.postman_collection.json` (named 'api-tests') is an ordered regression suite under a top-level 'Tests' folder with sub-folders `setup`, `sources`, `structures`, `translations`, `files`, `kleioset`, `exports`, `reports`, etc., that first invalidates stale users, generates scoped bearer tokens (`limited_token`, `tester_token`, `coordinator_token`), copies `reference_sources` into a per-run `test_sources` directory, then exercises CRUD and translation flows against those fixtures.

Runtime state is parameterised through two Postman environments — `environment.json` ('timelink-kleio reference', defaulting `endpoint` to `localhost:8089`) and `tests.postman_environment.json` (a separate 'api-tests' environment) — so the same collection can target different servers or Docker setups. Each request carries a `{{request_id}}` query/header value and asserts the matching `Request-id` response header, providing traceability across the chain. Authentication is uniform: every request uses Bearer auth with a token pulled from the Postman environment (`{{testadmintoken}}`, `{{tester_token}}`, …). Assertions are written inline as `pm.test(...)` scripts in each request's `event.listen='test'` block, checking status codes, response headers, and body content via Chai assertions.
