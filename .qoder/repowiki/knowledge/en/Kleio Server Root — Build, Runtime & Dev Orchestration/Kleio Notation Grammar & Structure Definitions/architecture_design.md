Two complementary sub-trees under this module:

- `syntax/` — language definition. `kleio_data.ebnf` is the canonical EBNF grammar for the Kleio notation (groups, elements, values, aspects). `syntax/python/kleio_parser.py` implements a hand-written, SAX-like recursive-descent parser that tokenises via a configurable `TOKENS` dict mirroring the EBNF named tokens (`GROUP_MARKER`, `ELEMENT_SEPARATOR`, etc.) and emits events through an abstract `KleioParserHandler` interface (`start_group`/`end_group`, `start_element`/`end_element`, `characters`). The parser tracks indentation level to determine nesting and supports both inline group bodies and standalone element lines.

- `src/stru/` — schema registry in YAML. `sources-structure.yaml` is the default entry point that `include`s `elements.yaml`, `groups.yaml`, and language-specific variants (`pt-elements.yaml`, `pt-groups.yaml`, `pt-parents.yaml`, `pt-sources-structure.yaml`). `elements.yaml` declares primitive types (`number`, `string64`, `text`, `date`, …) and domain elements (`id`, `name`, `obs`, `ref`, …), each with optional `source:` inheritance from another element. `groups.yaml` defines the entity graph (`kleio`, `historical-source`, `entity`, `event`, `person`, `relation`, …) using keys `position`, `guaranteed`, `also`, `contains`, `idprefix`, and `source:` for extension; it also includes `elements.yaml`. `system.yaml` is a minimal base include file. Parallel `.str` / `.srpt` / `.yaml` / `.json` variants (`gacto2.*`) are generated or alternate representations of the same structure.

Dependency direction: the Python parser depends only on the EBNF semantics (no codegen); the YAML schemas depend on each other via `- include:` directives and element/group `source:` inheritance. There is no runtime coupling between the parser and the schema files — consumers load one side or the other.
